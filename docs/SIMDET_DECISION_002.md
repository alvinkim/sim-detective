## 1. 요약

agent가 지적한 다섯 가지를 모두 받아들인다. D2는 6–20 mV로 한 번 시도하고, 회색지대가 나오면 포기한다. 재생성 전에 현재 작업 tree를 commit한다.

## 2. 수정

### A1. P2 확인 항목 2의 기준 (DECISION-001 3장)

"구분되는 비율이 우연 수준(약 5%)"을 다음으로 바꾼다.

- CC의 SOC0, ST 네 설계(cause × small / large) 각각에 대해 seed 200개로 delta chi2를 따로 계산한다. 저장된 24개로는 판단하지 않는다.
- 통과 기준: 평균 delta chi2가 0에 가깝고, 3.84를 넘는 비율이 5% 이하다.
- 3.84는 판정 경계로만 쓴다. 두 가설이 포함 관계가 아니므로 "p < 0.05"라고 적지 않는다.
- D2를 적용하면 설계 대신 크기 6, 10, 15, 20 mV의 네 지점에서 같은 계산을 한다.
- 결과 표를 `scenarios/GENERATION_REPORT.md`에 남긴다.

### A2. 대표 실험 인자 변경 (승인)

P2를 적용하면 `cc_run` 대표 인자 두 개가 SOC 기준으로 거부되어, "같은 전류를 이어가는 무의미한 실험"이 선택지에서 사라진다. 다음을 승인한다.

- `experiments.representative.cc_run`의 (15 A, 1,200 s)와 (25 A, 900 s)를 SOC 범위 안의 값으로 바꾼다. 제안값은 (15 A, 600 s)와 (25 A, 300 s)다.
- 조건: 대표 실험 9개가 모든 not identifiable 시나리오에서 거부되지 않아야 한다. 25 A `cc_run`이 여전히 useless로 분류되는지 확인한다.
- 이 변경은 `experiments.representative`에만 적용한다. agent에게 보이는 menu의 범위(`experiments.menu`)는 바꾸지 않는다.
- 무작위 기준선은 재생성 후 다시 계산한 값으로 적는다. README, 보고서, DECISION-001 D3의 "95%"는 그 값으로 바꾼다.

### A3. D1의 통계 방식 (DECISION-001 4장)

묶음이 4개인 bootstrap은 쓰지 않는다. D1을 다음으로 바꾼다.

- **identifiable 시나리오**: (regime, cause, size) 조합 단위 bootstrap 구간을 시나리오 단위 Wilson 구간과 함께 낸다.
- **not identifiable 시나리오, D2를 적용한 경우**: 시나리오 단위 Wilson 구간을 쓴다. 크기 구간별(13 mV 미만 / 이상) × cause 표를 보조로 낸다.
- **not identifiable 시나리오, D2를 적용하지 않은 경우**: 네 설계 각각의 비율을 표로 낸다. 결론 문장은 "네 설계 모두에서 X% 이상"처럼 범위로 쓰고, 24개를 합친 구간은 "4가지 설계 × 6회"라는 주석과 함께만 낸다.

### A4. D2의 실행 규칙 (DECISION-001 4장)

- 범위 6–20 mV로 한 번 시도한다.
- DECISION-001 3장의 확인 항목과 A1을 모두 통과하면 적용한다.
- 회색지대에 걸리는 시나리오가 하나라도 나오거나 확인 항목이 실패하면 D2를 포기하고 small / large(8, 16 mV)로 되돌린다. 하한을 올려 다시 시도하지 않는다.
- 결과와 무관하게, 시도한 범위와 실패한 경우의 수치를 `GENERATION_REPORT.md`에 남긴다.

### A5. 이미 끝난 일

- **단가**: 2026-11-15에 확인이 끝난 것으로 본다. DECISION-001 2장 표의 "단가 확인 후 실행"과 7장의 "단가는 확인되지 않은 상태"는 삭제한다.
- **thinking 요약**: 문서 확인은 끝난 것으로 본다. 남은 조건은 P6 실호출에서 두 model이 설정을 받는지 확인하는 것 하나다.
- **FOLLOWUP T6**: P4 승인으로 해결된 것으로 본다.

## 3. 진행 전 질문에 대한 답

1. **1–4번 반영 여부**: 모두 반영한다 (A1–A4). 대표 실험 인자 변경을 승인한다.
2. **D2 실패 시**: 포기한다 (A4).
3. **commit**: P1, P2 재생성을 시작하기 전에 현재 작업 tree를 한 번 commit한다. 그 뒤로는 다음 단위로 commit한다. push는 하지 않는다.
   - P1 + P2 + A2 적용과 재생성
   - D2 (적용한 경우)
   - 집계와 보고서 변경 (P3, P4, A3, P8)
   - P5 병렬 실행

## 4. 순서

1. 현재 작업 tree commit
2. P1, P2, A2 적용 → 재생성 → DECISION-001 3장 확인 + A1
3. D2 시도 → 통과하면 유지, 아니면 되돌림
4. P3, P4, A3, P8 집계 → mock 재실행
5. 여기서 멈추고 보고한다. P6 실호출과 pilot은 사용자 승인 뒤에 한다.
