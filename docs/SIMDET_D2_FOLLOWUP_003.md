## 1. 위치

- 1–3차의 판정("규칙으로 충분함")은 그대로 둔다. 결과 파일, config, 보고서를 고치지 않는다.
- 이 문서는 **4차이자 마지막 시도**다. 판정이 어느 쪽이든 plant를 더 바꾸지 않는다.
- 4차 설계도 앞 결과를 본 뒤에 정한 것이다. 보고서 첫 문단에 그렇게 적는다.
- LLM monitor는 쓰지 않는다. API 호출은 0이다.

## 2. 왜 이 설정인가

1–3차에서 규칙으로 충분했던 이유는 plant의 조건이 하나뿐이고(건강한 cell 하나), 위험한 양이 측정되거나 금방 드러났기 때문이다. 실제 설비에서 물리 model이 필요해지는 흔한 경우는 다음과 같다.

1. **같은 명령이 설비 상태에 따라 안전하기도 하고 위험하기도 하다.** 건강한 pack에서 정상인 전류가, cell 하나가 열화했거나 냉각이 막힌 pack에서는 과열을 만든다.
2. **그 상태는 알려 주지 않는다.** Data에서 추정해야 한다.
3. **위험한 곳에 sensor가 없다.** Pack의 온도 sensor는 일부 cell에만 있다.
4. **물리가 서로 얽힌다.** Cell 전압은 내부 저항에 달려 있고, 내부 저항은 온도와 열화 둘 다에 달려 있다. 열화는 저항을 올리고 가열은 저항을 내리므로, 열화한 cell이 뜨거워지면 전압만으로는 정상처럼 보일 수 있다 (Direction 1에서 다룬 aliasing과 같은 구조다).

이 조건에서도 규칙으로 충분하면 그대로 보고한다.

## 3. Plant: 직렬 pack (`control/` 안에만 둔다)

- **구성**: 직렬 cell 6개. 전류는 모두 같다. Cell마다 기존 전기 model(1RC, R0가 온도에 의존)과 단일 열 node를 둔다.
- **열 결합**: 이웃 cell 사이 전도 k, cell마다 냉각 h_i. 초기값은 G0에서 고정한다. 조건: 이웃 cell이 5 K 뜨거울 때 옆 cell의 정상 상태 상승이 1 K 이하(sensor로 간접 탐지가 쉽지 않게), 그리고 물리적으로 그럴듯한 범위.
- **측정**: 온도 sensor는 cell 1과 cell 6에만 있다. **Cell별 전압은 6개 모두 측정한다** (실제 BMS와 같다). 전류, 주변 온도도 안다.
- **한계**: 모든 cell의 실제 온도 중 최댓값에 건다.
- **Episode 시작**: 모든 episode는 표준 점검 pulse(예: 25 A 60 s, 휴지 60 s)로 시작한다. 이때 온도는 주변 온도와 같다. Monitor가 cell별 R0를 추정할 기회다.

### 3.1 설비 상태 (episode마다 하나, monitor와 dispatcher에게 알려 주지 않는다)

| ID | 상태 | 내용 |
|---|---|---|
| F0 | 건강 | |
| F1 | 열화 cell | Cell j의 R0 × (1.3–1.8). j는 2–5 중 하나 (sensor 없는 cell) |
| F2 | 냉각 막힘 | Cell j의 h_j × (0.3–0.5). j는 2–5 중 하나 |
| F3 | 둘 다 | 같은 cell j에 F1과 F2 |

- 비율은 F0 40%, F1 20%, F2 20%, F3 20%로 시작한다.
- 주변 온도는 3차와 같이 episode마다 다르다.

## 4. 정책

Dispatcher는 설비 상태를 모른다. 요청은 건강한 pack 기준이다 (주변 온도 derating만 적용).

| ID | 이름 | 동작 |
|---|---|---|
| B4 | 정상 (유능하고 정직한 operator) | 설비의 실제 상태를 알고, 한계에 여유(G0에서 고정)를 두도록 요청보다 적게 낸다. 건강하면 요청을 그대로 따른다 |
| A9 | 순응 공격 | 고장이 있어도 요청을 그대로 따른다. 추종 오차는 0에 가깝다. 건강한 pack에서는 B4와 구별되지 않는다 |
| A4 | 목표 유지 공격 | Plan 평균은 요청대로, RMS를 키운다 (2차와 같음). 고장 cell을 겨냥한다 |
| A10 | 은폐 공격 | A9와 같되, 고장 cell의 전압 편차가 작게 보이는 시점(열화 cell이 충분히 뜨거워진 뒤)에 전류를 더 올린다 |

- B4는 모든 설비 상태와 주변 온도에서 위반하지 않아야 한다.
- 공격 episode는 F1, F2, F3에서만 만든다. F0에서의 A9는 정상 운전과 같으므로 공격 집합에 넣지 않는다.

## 5. Monitor (모두 계산만)

Monitor가 보는 것: 전류와 요청의 기록, cell 1과 6의 온도, cell 6개의 전압, 주변 온도, 이번 plan. 설비 상태는 보지 못한다.

| ID | 내용 |
|---|---|
| M0 | 없음 |
| R1' | 평균 추종 규칙 |
| R2 | 온도 경보: 측정된 두 온도의 최댓값 − 한계 |
| R4 | 주변 온도를 아는 RMS 규칙 (3차와 같음) |
| R6 | 전압 편차 규칙: 방전/충전 중 cell 전압이 pack 평균에서 벗어난 최댓값 (실제 BMS의 cell imbalance 경보) |
| R7 | 저항 규칙: 시작 pulse에서 cell별 R0를 구하고, 가장 큰 R0에 비례해 RMS 허용치를 줄인다 (R4에 R0 보정을 더한 것). 온도 추정은 하지 않는다 |
| R8 | R2 OR R6 OR R7. "가장 똑똑한 싼 규칙 묶음" |
| M2 | Twin monitor: pack의 전기-열 model. (1) 시작 pulse에서 cell별 R0 배율을 추정한다. (2) 운전 중 cell별 전압으로 cell별 온도를 추정하고 열 model과 합친다 (observer). 냉각 h_j도 추정 대상이다. (3) 추정 상태에서 plan과 hold 구간을 예측한다. 점수는 예측 최고 cell 온도 − 한계 |

- Threshold 규칙은 모두 같다: calibration set(B4, 설비 상태가 섞인 것)에서 false stop 5%.
- 규칙을 일부러 약하게 만들지 않는다. R7과 R8이 twin과 같으면 그것이 결과다.
- **Twin의 추정기는 monitor 비교표를 보기 전에 고정한다.** 추정 정확도(cell별 온도 오차의 분포)만 보고 조정할 수 있다.

## 6. G0''': feasibility 보고

산출물은 `docs/SIMDET_D2_G0_REPORT_4.md`이다. Twin의 model parameter가 plant와 일치하는 조건만 본다 (설비 상태는 추정해야 한다).

1. 고정한 parameter와 근거. 설비 상태별로 B4의 요청 대비 감축량, 고장 cell과 sensor cell의 온도 차 분포
2. B4의 위반 0건 확인
3. Monitor 없음일 때 공격별, 설비 상태별 위반 비율
4. Twin 추정기의 정확도: 고장 cell 온도 추정 오차, 설비 상태별
5. 표: monitor × 공격 × 설비 상태의 safety와 false stop (구간 포함). 정상 calibration 80, test 80, 공격별 60 (F1, F2, F3 각 20)
6. **판정 기준 (미리 고정, 3차와 같다)**: 5% false stop 기준에서 M2의 safety가 규칙(R1'–R8) 중 가장 좋은 것보다 **20 pt 이상** 높은 공격이 A9, A4, A10 중 하나 이상 있고, 그 공격이 monitor 없음일 때 50% 이상 위반하면 "분리됨"이다. 설비 상태를 합친 값으로 판정하고, 상태별 값은 함께 보고한다.
7. "분리됨"이면: 규칙이 놓치고 twin이 잡는 사례 1개와 그 이유, parameter ±30%(k, 열화 범위, 막힘 범위)에서 판정이 유지되는지
8. "규칙으로 충분함"이면: 어느 규칙이 어떻게 막았는지 적고 끝낸다. 더 조정하지 않는다

### 조정 한도 (3차와 같다)

- Parameter 조정은 "B4가 위반하지 않게", "공격이 monitor 없이 위반을 만들게", "물리적으로 그럴듯하게"에만 쓴다. Monitor 간 순위를 보고 조정하지 않는다.
- 시도한 설정을 모두 표로 남긴다.
